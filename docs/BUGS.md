# BUGS

Known bugs and risks, each verified by Claude in the code or the primary source (Decision 26) unless it says "unverified". Claude is the only writer. A verified bug becomes a card when the owner picks it; remove the entry when its card merges. Test-report fails (pass or fail, card number, screenshot) are added here or become a card.

- **Assist screen header is cramped on a phone (owner screenshot 2026-10-31, not carded; cause only partly seen in the code).** `src/components/AssistantView.tsx` header: the title `<h2>` has `shrink-0` inside a `min-w-0` group, and the right group (Generate cover button, profile picker capped at `max-w-[7rem]`, reset) is `shrink-0`, so on a narrow screen the word "Assistant" touches the cover button. In the same screenshot the first Forge tab ("Details") sits flush against the left edge of the tab strip with its icon clipped; the strip in `ContextBar.tsx` is `overflow-x-auto`, so it may just be scrolled by a few pixels. Not reproduced.
- **Export dialog vs toast mismatch reported from screenshots, not reproduced (2026-10-30).** The code prints "API keys were left out" only when the checkbox was unchecked at the moment of Export. Probably the box was unchecked before the tap; unverified.
- **Forge ignores Android themed icons (owner screenshots 2026-10-30, cause confirmed by the owner: "adopt system colours").** With the setting on, every app with a monochrome icon is recoloured and Forge stays full colour in a light plate, because the web manifest has no monochrome icon. The maskable icon itself is fine. Whether Chrome uses a `monochrome` manifest icon for installed web apps is unverified. Low priority polish; not carded.
- **Standard PNG export drops the cover (verified 2026-10-30, carded as 029).** `exportCardData(card, 'png', ...)` in `src/io/index.ts` forwards only `options.basePng` to `writeCardToPng`, and no caller sets it (only `visualCardExporter.ts` does). So the Editor's PNG export and the Library's single and bulk PNG exports write the card into a 1x1 blank image (`createDummyPng`). JSON and CHARX exports are not affected. "Verify Export" does not check the image.
- **Lorebook simulator budget order is the reverse of SillyTavern (verified in the code; the ST side is research 001 claim 2, not re-read).** `src/utils/lorebookScan.ts` sorts activated entries by weight, then `a.order - b.order`, then fills the token budget until the first overflow; research 001 says SillyTavern sorts `b.order - a.order` (higher `order` survives, low numbers drop first). `lorebookConflict.ts` also sorts by order ascending, for conflicts. Not carded; Task 024 covers the warning wording only.
- **Cover generator sends card text to a third party with no notice (verified 2026-10-30, not carded).** `generateCharacterLogoBytes` (`src/utils/logoGenerator.ts`) puts the name, up to 5 tags and the first 120 characters of description plus personality into a GET URL to `image.pollinations.ai` (used from `EditorView` and `AssistantView`). No "Sent to ..." line is shown (Decision 7 covers AI assist; this is a separate image service). `docs/ARCHITECTURE.md` says only providers and Chub are contacted; that is incomplete.
- **Guide claims Agnaistic compatibility without evidence (verified in the code 2026-10-30, not carded).** `src/components/GuideView.tsx` line 311 says PNG and CHARX exports are "compatible with SillyTavern & Agnaistic". No Agnaistic fixture or adapter exists (Agnai appears only in a comment in `src/utils/normalizeLorebook.ts`), and `docs/PLATFORM_SUPPORT.md` lists other frontends as planned. This breaks the evidence-led rule in `docs/PRODUCT_VISION.md`. It is not shown to be false, only unproven. A one-line wording fix that fits the `small fix:` lane; the owner picks the wording.
- **Saved card shows "Unsaved" two seconds after saving (ROADMAP 6b, verified in the code, not carded).** `cardSlice.ts` resets `saveState` from `saved` to `idle` after 2 s, and `ContextBar.tsx` shows `idle` as "Unsaved".
